# i18n (PL/EN)

The app ships in English and Polish with i18next + react-i18next, JSON v4 plurals and bundled resources
([#37](https://github.com/alimek/budget-lens-offline/issues/37), [#77](https://github.com/alimek/budget-lens-offline/issues/77),
[ADR 0009](decisions/0009-english-and-i18n.md)). Code lives in `apps/mobile/src/i18n/`.

## Resources and namespaces

- One JSON file per language and namespace: `src/i18n/locales/<language>/<namespace>.json`.
- **English is the source of truth.** Every key is added to the English file first; Polish sits alongside and may lag
  behind.
- `translation` is the default namespace (app shell, shared strings and the existing keys). A new feature adds its own
  namespace (e.g. `items`): create `locales/en/items.json` and `locales/pl/items.json`, register both in
  `src/i18n/resources.ts`, and use `useTranslation("items")`.
- Keys are type-checked: `src/i18n/i18next.d.ts` types `t()` keys and namespaces from the English resources, so a
  key that is not in English fails `pnpm typecheck`.
- Plurals use i18next JSON v4 suffixes (`_one`, `_few`, `_many`, `_other` for Polish). They need `Intl.PluralRules`,
  which Hermes lacks: `apps/mobile/index.ts` loads the `@formatjs/intl-pluralrules` polyfill with en/pl data first.

## Fallback

`fallbackLng` is English. A key that is missing in Polish, or an empty string (the placeholder written by
`i18n:extract`), renders the English text at runtime (`returnEmptyString: false`; covered by `src/i18n/i18n.test.ts`).

## Language and the in-app override

- The preference is `LanguagePreference` from core: `"system"`, `"en"` or `"pl"`. `"system"` follows the device
  (per-app) language from `expo-localization` and falls back to English for unsupported languages
  (`resolveLanguage`). The `expo-localization` config plugin declares `supportedLocales: ["en", "pl"]` in
  `app.json`, so iOS and Android 13+ offer the app's language in the system settings (per-app language); this is
  native config, so changing it needs a new development build.
- `useAppLanguage()` returns the `language` i18next is currently rendering, the `preference` and
  `setLanguagePreference()`, which switches the language at runtime without a restart. `language` equals the resolved
  language but changes only once i18next has switched, so it never gets ahead of `t()`. `useLanguage()`
  (`src/ui/use-language.ts`) gives the language for `Intl` formatting.
- `I18nProvider` takes an optional `preferenceStore` (`load()`/`save()`, synchronous so the first frame is already in
  the right language). Without it the preference starts as `"system"` and lives in memory. Persistence belongs to
  settings persistence ([#78](https://github.com/alimek/budget-lens-offline/issues/78)) and the non-secret `bl.lang`
  mirror ([#36](https://github.com/alimek/budget-lens-offline/issues/36)). The language picker UI belongs to the
  Settings screen (#78).

## Formatting

Numbers and money go through core `formatMoney` and native `Intl` in the app language
([ADR 0012](decisions/0012-native-intl-money-formatting.md)); dates through `src/ui/calendar-date.ts`. The i18n layer
adds no formatting of its own.

## Key extraction, no CI check

`pnpm i18n:extract` (i18next-cli, `apps/mobile/i18next.config.ts`) adds keys found in the code to the locale files,
with empty Polish placeholders. It never removes keys, because template-literal keys are invisible to static analysis.

There is **no translation check in CI, `pnpm check` or Lefthook** (no completeness, missing-key or unused-key check,
neither blocking nor a report): final owner decision on
[#37](https://github.com/alimek/budget-lens-offline/issues/37#issuecomment-6263102054). A missing Polish string ships
as English.
